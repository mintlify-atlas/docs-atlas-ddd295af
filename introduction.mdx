## Why Airbyte?

Data teams at thousands of companies use Airbyte to solve the fundamental challenge of data movement:

- **Breadth** — 600+ connectors covering APIs, databases, files, and data warehouses. If a connector doesn't exist, build it in minutes with the no-code Connector Builder.
- **Reliability** — Built-in retry logic, error handling, and observability ensure your pipelines keep running.
- **Flexibility** — Run it your way: self-hosted on Kubernetes, managed by Airbyte Cloud, or embedded via the API.
- **Developer-first** — Full API, Terraform provider, Python SDK (PyAirbyte), and MCP server for AI agents.

## How it works

Airbyte moves data using an **ELT** (Extract, Load, Transform) pattern:

1. **Extract** — A source connector reads data from your source system (Postgres, Salesforce, GitHub, etc.)
2. **Load** — Airbyte loads raw data into your destination (BigQuery, Snowflake, S3, etc.)
3. **Transform** — Use dbt, SQL, or your preferred tool to transform the raw data in your warehouse

<Note>
Airbyte does not transform data during transit. Raw data is loaded as-is, giving you full fidelity and control over transformations.
</Note>

## Key concepts

| Concept | Description |
|---------|-------------|
| **Source** | The system you're reading data from (e.g., Postgres, Salesforce) |
| **Destination** | The system you're writing data to (e.g., BigQuery, Snowflake) |
| **Connection** | A configured pipeline between a source and destination |
| **Sync** | A single execution of a connection that moves data |
| **Stream** | A logical table or dataset within a source or destination |
| **Connector** | A packaged integration for a specific source or destination |
